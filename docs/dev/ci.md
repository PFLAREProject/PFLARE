# CI (agent reference)

Workflow: `.github/workflows/ci_build.yml` (push/PR to main, monthly cron, manual dispatch). Every job builds a Docker image and runs the full test suite inside it.

Jobs, grouped
- GNU debug/opt: `gnu_debug`, `gnu_opt` (pushes `stevendargaville/pflare:latest` on non-PR events), `gnu_opt_64_bit`.
- Leak/memory checks: `*_malloc_dump` variants run with `-malloc_dump` and fail if `PetscTrMalloc` appears in the test log; `gnu_debug_valgrind`, `gnu_debug_kokkos_valgrind`.
- Runtime checks: `gnu_debug` builds the C/C++ core with the address and undefined behaviour sanitizers and the Fortran interface and Fortran tests with gfortran's runtime checks (`dockerfiles/Dockerfile` build args `EXTRA_CFLAGS`/`EXTRA_CXXFLAGS="-fsanitize=address,undefined"`, `EXTRA_FFLAGS="-fcheck=all -g -fbacktrace -fsanitize=address,undefined"`, `ASAN_OPTIONS=detect_leaks=0`, `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=1`) and runs `make check` and the full suite, so an out-of-bounds access, use after free or undefined behaviour in the C, or an out-of-bounds index or unallocated array in the Fortran, aborts the test. The sanitizer is on `FFLAGS` too so the Fortran test drivers link its runtime first, which the address sanitizer requires. The Python bindings are not built in this job (an uninstrumented Python can't load the instrumented library without an `LD_PRELOAD` of libasan; `gnu_opt` tests Python), so the Python tests print that they were skipped. LeakSanitizer is off (MPI and PETSc keep memory until exit); the `*_malloc_dump` and valgrind jobs check for leaks. To reproduce locally, in the image with `PETSC_ARCH=arch-linux-c-debug`, add those flags to `CFLAGS`/`CXXFLAGS`/`FFLAGS` and export the two options.
- No Fortran: `gnu_opt_no_fortran` (PETSc `--with-fc=0`, gfortran and `f951` deleted from the image so any Fortran compile fails) and `gnu_debug_no_fortran_bindings` (PETSc `--with-fortran-bindings=0` with gfortran present, so `FC` is set but PETSc has no Fortran modules) build `dockerfiles/Dockerfile_no_fortran` with build args `BASE_ARCH` (an arch of `stevendargaville/petsc`), `ARCH` (the new arch) and `FORTRAN` (`no_fortran` or `no_fortran_bindings`). There is no such base image, so the Dockerfile configures PETSc again into the new arch with the options of `$PETSC_DIR/$BASE_ARCH/lib/petsc/conf/reconfigure-$BASE_ARCH.py`, copying the base arch's `externalpackages` so nothing is downloaded; for `no_fortran` it drops `--download-fblaslapack`/`FOPTFLAGS` and links the base arch's `libfblas.a`/`libflapack.a` (copied to `/build/fblaslapack`, with `-lgfortran -lquadmath`), so the BLAS/LAPACK is the same as `gnu_opt`'s. Configure plus `make all` (with petsc4py) takes about 10 minutes. Then, with `CFLAGS/CXXFLAGS/CPPFLAGS="-Werror -Wall"` and no `FFLAGS`: `make`, `make python`, `make check` (must print "Fortran check skipped (PETSc configured without Fortran bindings)"), `make tests`, a check that no `.mod`, `src/fortran/*.o` or Fortran test driver was built and that `nm -D lib/libpflare.so` has no gfortran symbol, `make install` to `/tmp/pflare_install` (must write no `.mod`), and `python/ex2.py` run against the installed bindings. PFLARE detects both cases from `PETSC_USE_FORTRAN_BINDINGS` alone (`docs/dev/testing.md`, Fortran gate).
- Kokkos: `gnu_opt_kokkos`, `gnu_opt_64_bit_kokkos`, `gnu_opt_omp_kokkos`, `gnu_debug_no_mpi_kokkos`, `gnu_debug_kokkos_single_prefix` (single precision).
- Other: `intel_opt`, `macos_debug`, `macos_64_bit_kokkos`, `notebook_tutorial`, `gnu_petsc_config` (builds PETSc `main` with `--download-pflare` and gates the Sphinx doc build).

Images
- Base images: `stevendargaville/petsc` (`dockerfiles/Dockerfile`, also `Dockerfile_no_fortran`, which configures its own PETSc arch on top) and `stevendargaville/petsc_kokkos` (`dockerfiles/Dockerfile_kokkos`); published result: `stevendargaville/pflare:latest`.
- Inside the image: PFLARE at `/build/PFLARE`, tests at `/build/PFLARE/tests`, PETSc at `/build/petsc`.
- To reproduce a CI failure locally: `docker pull` the latest image first, then run the failing make target inside it.

Enforced flags (why "fix all compile warnings" is a hard rule)
- Non-Kokkos builds: `FFLAGS="-Werror -Wall -ffree-line-length-132 -ffixed-line-length-132"`, `CFLAGS/CXXFLAGS/CPPFLAGS="-Werror -Wall"` (the no-Fortran jobs pass no `FFLAGS`).
- Kokkos builds: `-Wall -Werror -Wunused-result`, `CXXFLAGS` additionally `-std=c++20`.
- Default runtime options in the image: `PETSC_OPTIONS="-on_error_abort -fp_trap on"` (Kokkos image sets the aijkokkos/kokkos mat/vec types too).

Output-parser checks (part of `gnu_opt`)
- `python/run_parse_tests.py` with `tools/parse_pflare_output.py` runs inside the image (`PFLARE_TESTS_DIR`, `PFLARE_TOOLS_DIR` env vars) and asserts: grid complexity < 3.0, reuse storage == 0.0, KSP iteration counts below their maxima. Changes that alter PFLARE's printed stats/timing output can break these.

GPU tests (`.github/workflows/gpu_tests.yml`, manual trigger only)
- `runs-on: cirun-gpu-runner--<run id>`: Cirun (cirun.io GitHub App, free for public repos) reads `.cirun.yml`, rents a Vast.ai RTX 3060 container from `stevendargaville/petsc_kokkos_cuda:latest` (CI_builds `Dockerfile_petsc_kokkos_cuda`: PETSc main debug, Kokkos CUDA sm_86, CUDA-aware MPICH, no PFLARE), and destroys it when the job ends. Gated by the `protected-manual-builds` environment; no secrets are exposed to the job.
- Steps: record hardware (fails if the GPU's compute capability cannot run the image's arch), PETSc `make check` (deliberately not run in the image build), then PFLARE `make`, `make python`, `make check`, `make tests` with the Kokkos CI flags (`PFLARE_KOKKOS_DEBUG` not set for now). The `smoke_only` input runs only the hardware step.
- The image arch (`CUDA_ARCH` in CI_builds) and `instance_type` in `.cirun.yml` must be changed together. The image's ENV is not visible to the runner session on Vast.ai, so the workflow sets `PETSC_DIR`/`PETSC_ARCH`/`PATH` itself.
